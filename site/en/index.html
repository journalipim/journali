journali does not overwrite.

Product data changes every day: imports from the ERP, corrections, new images, new regulations. Whoever wants to know what applied three years ago restores a backup and hopes the program version still fits.

In journali every change is a new, numbered entry with author and time. The current state is derived from the journal. Values, names, assignments, releases and the data model itself are entries – the single source of truth.

Features

More than a change history.

⎘ Versions

One click creates a version: a pointer to the journal state plus the documents that went out. Immutable, with a retention period; it can be withdrawn but not deleted.

⊞ Editing like in a spreadsheet

Inline editing in the cell, keyboard through the list, bulk editing: drag a range, fill, paste from the clipboard. The journal runs alongside.

✓ Data quality that grows

Rules for required fields, patterns, numbers, list values and translations apply to every new node and to existing data. A release requires completeness.

◈ EU obligations

Checks as plugins for the Digital Product Passport (ESPR), packaging data (PPWR) and environmental claims (EmpCo): map data points, see gaps, check whole subtrees.

⌗ ETIM and GS1 GPC

Read releases, assign classes, map characteristics to your own attributes, see completeness per class; output as ETIM BMEcat.

🗣 Translations that follow

Every language has its own state. If the source text changes, you see what to update; jobs go out as XLIFF and come back.

✦ AI, your choice

The team connects its own provider and key; the key lies with the server, never in the journal and never in the browser. Every suggestion is accepted, changed or discarded, and what is accepted is in the journal with its author. Without a key the plugins work rule-based.

✦ Product advisor

A chat window for your website, added with one script tag: visitors ask in their own words, the advisor answers from the products of a publication tree – with follow-up questions, comparison and excerpts from your documents, also without AI. Form of address and tone are adjustable; AI agents ask the same questions over MCP; logged-in customers can get their own view. The service runs in its own container, also on Unraid.

✦ journali advisor

How do I …? Where is …? Why is …? The assistant for using journali finds the matching sections of the help, names places in the interface as links and, at a node, the reasons from its data.

Questions and answers.

What is journali?

journali is a product information management (PIM) system that stores every change to product data as an immutable entry in a journal. The current state is derived from the journal; earlier states stay available.

Is journali open source?

Yes. journali is licensed under the GNU Affero General Public License, version 3 (AGPL-3.0). The source code and the image are public.

Can I run journali myself?

Yes. journali runs as a Docker package with PostgreSQL and as an app on Unraid. Media are stored in Postgres, in the file system or in S3-compatible object storage.

What is a version?

A version is a pointer to the journal state of a product plus the documents delivered for that state. It is immutable, has a retention period and can be withdrawn but not deleted.

Is journali ready for production?

journali is a test version, provided solely for testing and evaluation. It is not suitable for production use yet.
