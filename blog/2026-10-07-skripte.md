Eine Liste, die zwei Systeme zusammenführt. Ein Abgleich, der jeden Montag läuft. Eine Übergabe an ein System, das außer euch niemand so braucht. Solche Aufgaben gibt es in jedem Haus, und für keine lohnt sich ein eigenes Plugin. **In journali schreibt ihr stattdessen ein Skript – in der Oberfläche, am selben Tag.**

## Ein Skript steht im Journal

Der Quelltext liegt nicht in einem Verzeichnis auf dem Server, sondern **im Journal**. Damit ist er versioniert, rückholbar und in jeder Sicherung enthalten wie alles andere. Ein Skript schreibt ihr unter **⌨ Skripte** in einem Editor mit Hervorhebung und Tastenkürzeln, und es gehört eurer Instanz: Nichts wird mitgeliefert und nichts signiert, was ihr selbst geschrieben habt.

Ein Geheimnis gehört nie in den Quelltext. Im Journal lässt sich nichts löschen, darum kommen Zugangsdaten aus einem **Zugang** – dazu gleich mehr.

## Der Kopf ist das Formular

Jedes Skript beginnt mit einem Kopf, der Bezeichnung und Parameter deklariert. Daraus baut journali das Formular – Programm und Maske bleiben zusammen und laufen nicht auseinander:

```js
export const meta = {
  label: 'Knoten als CSV',
  params: [{ key: 'datei', label: 'Dateiname', type: 'text', default: 'knoten.csv' }],
}

export default async (ctx) => {
  const knoten = await ctx.api.get('/api/tree')
  const tabelle = knoten.map((n) => ({ id: n.id, name: String(ctx.lib.get(n, 'label', n.id) ?? '') }))
  return ctx.out.file(ctx.params.datei, ctx.lib.csv(tabelle, { columns: ['id', 'name'] }))
}
```

Wer das Skript später ausführt, sieht nur das Formular. **Den Quelltext muss er dafür nie öffnen.**

## Ergebnis: eine Tabelle, ein Text oder eine Datei

Ein Skript liefert, was die Aufgabe verlangt: eine **Tabelle** mit Spalten und Zeilen, einen **Text** oder eine **Datei** im Fach `out/`. Tabelle und Text zeigt die Ansicht an, die Datei bietet sie zum Herunterladen an. Eine Auswertung entsteht so ohne eine Zeile Oberflächencode.

## Drei Wege, ein Skript zu starten

- **Von Hand** in der Ansicht: ▶ Ausführen, Ergebnis ansehen.
- **Als Job mit Zeitplan** im Tasker, mit Fächern, Protokoll und Zeitgrenze wie jeder andere Job.
- **Von einem anderen System** über die Schnittstelle: `POST /api/scriptum/scripts/{key}/run` mit einem Token.

Es ist immer dasselbe Skript und dieselbe Maschinerie. **Von Hand ausführen legt einen Job an** – ihr seht den Lauf also auch unter ⏱ Jobs, mit demselben Protokoll.

## Fremdsysteme anbinden: ein Zugang und ein Skript

Ein neues System anzubinden braucht kein gebautes Plugin. Ihr richtet einen **Zugang** vom Typ HTTP ein – Adresse und Anmeldung (ohne, Bearer, Basic oder ein eigener Kopf) – und sprecht ihn im Skript mit `ctx.zugang(...)` an: lesen, schreiben, ändern, löschen. **Das Geheimnis kennt nur der Server.** Er hängt die Anmeldung an die Anfrage, und das Skript sieht das Token nie. Die Weiterleitung bleibt auf den einen Host des Zugangs beschränkt.

Auch Schnittstellen, die mehr als einen Rumpf verlangen, gehen: Mit `roh(...)` bekommt das Skript die ganze Antwort samt Kopfzeilen und kann etwa erst einen Sicherheitstoken holen und dann damit schreiben.

## Beispiele zum Anfangen

Niemand muss bei null beginnen. journali bringt **geprüfte Beispiele** mit, die ihr mit **＋ Beispiel …** in den Editor ladet und anpasst:

- CSV-Export eines Teilbaums,
- ein Fremdsystem über einen Zugang lesen,
- Knoten an ein Fremdsystem senden,
- ERP-Daten über OData lesen, schreiben und abgleichen,
- Knoten je Wert zählen,
- Schritte, Snapshot und Helfer.

Ein Fremdcode-Markt ist das bewusst nicht: **journali zieht nie von selbst fremden Code und führt ihn aus** – was ihr ladet, wählt ihr.

## Direkt am Knoten

Ein Skript mit `nodes: true` im Kopf erscheint im **Kontextmenü des Baums**. Ihr markiert mehrere Knoten, klickt einmal – und das Skript läuft **einmal auf allen**. Die Kennungen kommen als Parameter an. So werden Skripte zu kleinen Helfern direkt dort, wo ihr arbeitet.

## Schritte und Helfer

Längere Skripte gliedert ihr mit `ctx.step`: Jeder Schritt steht mit Dauer im Protokoll, lässt sich gegen ein JSON-Schema prüfen und als **Snapshot** ins Fach `out/` legen. Dazu kommen geprüfte Helfer in `ctx.lib`: `csv`, `parseCsv`, `chunk`, `retry`, `get` und `sleep`. Pakete aus dem Netz sind nicht nötig.

## Wer darf was

Zwei Rechte, die nicht dasselbe sind:

- **Skripte schreiben** ist ein **Administratorrecht**: Wer es hat, kann alles, was der Serverprozess kann.
- **Ausführen** richtet sich nach dem Recht, das am Skript steht. So bedient jemand mit dem Recht zu lesen eine Auswertung, ohne dass ihr dieses Recht an jede Rolle vergeben müsst.

Ein Lauf bekommt ein Token mit der Rolle, die am Skript steht. **Ein Skript darf in journali nie mehr als ein Anwender mit dieser Rolle.**

## Ehrlich dazu

Ein Skript läuft als Prozess auf dem Server und nie im Serverprozess selbst. Das Token begrenzt, was es **in journali** darf; was es darüber hinaus tut, etwa im Netz oder im Dateisystem, begrenzt das Betriebssystem. Darum ist das Schreiben ein Administratorrecht, und die Oberfläche sagt es an der Stelle, an der ihr ein Skript anlegt. Jeder Lauf hat eine Zeitgrenze – 60 Sekunden als Vorgabe, am Skript einstellbar bis zu einer Stunde. Ein Fehler im Skript ist eine Meldung im Ergebnis und kein Absturz.
